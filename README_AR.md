# المنصة الأكاديمية الرقمية — Flutter Android

نسخة أولية مستقلة لتطبيق Android لمشروع «تصميم وتطوير منصة أكاديمية رقمية لإدارة ومتابعة العملية التعليمية».

## ما الذي تتضمنه النسخة؟

- واجهة عربية من اليمين إلى اليسار (RTL).
- شاشة تسجيل دخول تجريبية واختيار نوع الحساب: طالب، مدرس، رئيس القسم، إدارة الكلية.
- لوحة تحكم تتغير حسب نوع الحساب.
- صفحات رئيسية للمقررات والإشعارات والحساب الشخصي.
- واجهات تجريبية لخدمات المحاضرات، الواجبات، الحضور، التقدم، الشكاوى، التقارير وإدارة المستخدمين.
- بيانات أمثلة داخل التطبيق فقط؛ لا يوجد اتصال بخادم أو قاعدة بيانات دائمة في هذه المرحلة.

## المتطلبات

- Flutter SDK حديث متوافق مع Dart 3.3 أو أحدث.
- Android SDK وأدوات بناء Android.
- اتصال إنترنت أول مرة لتنزيل حزم Flutter القياسية.

## فتح المشروع في Klencod IDE

1. فك ضغط الأرشيف.
2. افتح مجلد `academic_platform_flutter` في Klencod IDE.
3. إذا كانت البيئة تتطلب مجلد Android الأصلي غير الموجود في الأرشيف، أنشئ مشروع Flutter جديدًا باسم `academic_platform` من داخل IDE، ثم انسخ مجلد `lib` وملفات `pubspec.yaml` و`analysis_options.yaml` و`.gitignore` من هذا المشروع إلى المشروع الجديد مع استبدال الملفات عند الطلب.
4. افتح الطرفية في جذر المشروع، حيث يوجد `pubspec.yaml`.
5. نفّذ:

```bash
flutter pub get
flutter analyze
flutter run
```

## إنشاء APK

لإنشاء APK تجريبي:

```bash
flutter build apk --debug
```

ولإنشاء APK إصدار:

```bash
flutter build apk --release
```

عادةً يظهر الملف الناتج في:

`build/app/outputs/flutter-apk/app-release.apk`

## تجربة التطبيق

- افتح التطبيق.
- أدخل أي اسم مستخدم وكلمة مرور غير فارغين؛ تسجيل الدخول تجريبي فقط.
- اختر نوع الحساب لتجربة لوحة التحكم المناسبة.
- افتح المقررات والخدمات من الشريط السفلي ولوحة الخدمات.

## ملاحظات مهمة قبل الاستخدام الحقيقي

- لا تستخدم هذه النسخة لإدارة بيانات طلاب حقيقية بعد؛ المصادقة والبيانات تجريبية.
- لا يوجد حفظ دائم للبيانات أو مزامنة بين الأجهزة.
- المرحلة التالية المطلوبة: تحديد مخطط قاعدة البيانات، ثم إنشاء API آمن وخادم للمستخدمين والمقررات والحضور والواجبات، وإضافة تخزين ملفات المحاضرات وصلاحيات فعلية.
- يجب عدم تخزين كلمات المرور كنص صريح؛ تُدار المصادقة في الخادم باستخدام آلية آمنة وتجزئة مناسبة لكلمات المرور.

## أيقونة التطبيق

أُرفقت الأيقونة في `assets/app_icon.png`، وأُضيف إعداد توليد أيقونة Android إلى `pubspec.yaml`. بعد فتح المشروع وتشغيل الطرفية في مجلد المشروع نفّذ:

```bash
flutter pub get
dart run flutter_launcher_icons
flutter run
```

ثم لبناء APK:

```bash
flutter build apk --release
```

إذا كانت بيئة Klencod لا تسمح بتنزيل حزمة `flutter_launcher_icons`، أخبرني برسالة الخطأ؛ يمكن ضبط ملفات أيقونات Android يدويًا.

## إصلاح بناء APK على Klencod IDE / GitHub Actions

تمت إضافة ملف سير عمل جاهز في:
`.github/workflows/build-apk.yml`

سبب الخطأ السابق أن المشروع لا يحتوي على مجلد `android/` وملف `android/app/build.gradle` الذي يتوقعه مسار البناء. يقوم سير العمل الجديد بإنشاء ملفات منصة Android تلقائيًا بواسطة:

```bash
flutter create --platforms=android --project-name academic_platform .
```

ثم يجلب الحزم، ويولّد الأيقونة، ويفحص الكود، ويبني APK ويرفعه كـ Artifact.

### الاستخدام
1. ارفع محتويات هذا المجلد إلى مستودع GitHub الخاص بالمشروع، مع إظهار الملفات المخفية مثل `.github`.
2. افتح تبويب **Actions** في GitHub.
3. اختر **Build Android APK** ثم **Run workflow**، أو ادفع التعديلات إلى الفرع `main`.
4. بعد نجاح التشغيل افتح نتيجة الـ workflow، ثم نزّل Artifact باسم `academic-platform-android-apk`.

ملاحظة: لا يتضمن الأرشيف APK جاهزًا؛ يجب تشغيل Workflow في GitHub لبنائه في بيئة Flutter/Android.


## إصلاح خطأ عدم وجود android/app/build.gradle

إذا كان سجل البناء لا يعرض خطوة `Generate Android platform files`، فهذا يعني أن GitHub يشغّل ملف Workflow قديمًا أو أن التعديلات لم تُرفع إلى المستودع. ارفع محتويات هذا المشروع إلى المستودع مع المجلد المخفي `.github/workflows/`، ثم تحقق من ظهور الخطوات التالية في سجل Actions:

1. `Generate Android platform files`
2. `Verify Android Gradle files`
3. `Get Flutter dependencies`
4. `Build release APK`

لا تحذف مجلد `.github` عند الرفع. بعد نجاح البناء نزّل APK من قسم Artifacts في صفحة تشغيل Workflow.
